# Takeboard — 无限画布视频工作台

一切产物皆 **take**，永不覆盖。排列组合，推倒重来。

面向的是长片级的创作流程：画布上摆素材位，每个位置下面挂一叠版本（take 栈），
上游重跑不会悄悄改掉下游——要改，得显式**重新引脚**。

## 跑起来

```bash
cd D:\AI\repos\takeboard
npm run build          # 构建前端到 dist/web
npm run start          # 服务 → http://127.0.0.1:4317
# 或者开发模式（画布热更新，5317 端口，API 代理到 4317）
npm run dev
```

重启服务：`powershell -File scripts\restart.ps1`（只杀 4317，绝不碰 8188/8888）

## 三个概念，记这三条就够

| 概念 | 是什么 | 为什么 |
|---|---|---|
| **take** | 节点下的一版产物。跑一次多一版，旧版永远在 | 素材是不可再生资源，删了就没了 |
| **引脚 activeTake** | 节点的「当前版本」指针 | 切引脚 = 换用哪一版，不动任何文件 |
| **边上的 pin** | `active` 跟随上游当前版本；`<takeId>` 钉死那一版 | 这是「推倒重来」的安全带：重跑上游不会毁掉已经调好的下游 |

每个 take 还记着 **provenance**（`inputs: nodeId → takeId`），所以「这一版是从哪几版生出来的」永远查得到，
「沿链重演」也有据可依。

## 画布操作

- **空白处双击** → 加一个图片节点
- **拖节点右侧圆点**到另一个节点 → 连线
- **点节点上的 v 号** → 切引脚（下游没钉死的会跟着变）
- **▶ 跑一版** → 用当前参数新增一版（不覆盖）
- **⚄ 抽 N 版** → 同一套参数连跑 N 版，种子逐个递进（出量靠它，选优靠眼睛）
- **⟳ 下游** → 从这个节点起，沿链把所有下游节点重跑一遍
- **⤓ 登记** → 把本地已有文件登记成 take（外拍的素材、别处出的片子）
- **Ctrl+Shift+R** → 刷新画布

### 右键（浏览器默认菜单已被接管，四个位置各有一套）

| 右键在哪 | 能干什么 |
|---|---|
| 空白 | 在光标处加文本/图/视频/算子节点、适应视图、刷新、释放 8888 |
| 节点 | 跑一版、抽 4 版、重跑下游、**切引脚（列出全部版本）**、登记、重命名、删节点 |
| 连线 | 跟版 / **钉死到指定版本** / 删连线 |
| take 号（v1 v2 …） | 钉为当前版本、删除这一版 |

右侧 Inspector：改提示词/种子/尺寸/时长、选模板、定抽卡张数，看 take 栈，看 provenance，删节点。

右侧「⚙ 设置」：两个 ComfyUI 实例（生图 8888 / 出片 8188）的在线状态、端口、启动命令、**一键启停**，
外加项目级的模型模板 / ffmpeg 路径 / 释放策略。实例配方存 `data/machine.json`——换机器改它，不用改代码。

## 版本怎么不打架

节点上有一条**入边条**：`← 提示词 v2`，说的是这条入边现在生效的是上游第几版。

- 上游切引脚 → 入边条的数字**当场跟着变**，连线标签也从「跟版 v1」变成「跟版 v2」。
- 边被钉死 → 入边条标琥珀色写「钉死 vN」，上游怎么切它都不动。
- 本节点当前那一版**当时**吃的是哪版记在 `inputs` 里；和现在生效的版本对不上，入边条标黄
  `← 提示词 v1 · 本版还是 v2`——一眼看出这一版过期了，要不要重跑自己定。

引脚解析只有一份实现（`server/store.ts` 的 `resolveTake`），CLI、作业、UI 都走它。
回归检查：`npm run check:pin`（真起作业，验「切引脚 → 下游改吃新版」和「钉死 → 不跟着动」）。

## 提示词怎么流

**连线即数据流。** 文本节点连到生图/出片节点，那个节点的提示词就来自它——改一次词，
所有下游节点下一次跑都跟着变。优先级：

`本次显式给的（命令行 / 面板）` > `上游文本节点的当前版本` > `上一版继承下来的`

第二条必须排在第三条前面：不然改了上游的词，下一版还是会被上一版继承的旧提示词压住，
连线就成了摆设。要试单点差异，就在节点上直接给提示词（第一优先级），别去断线。

**换模板**同理：`params.workflow` 优先于项目默认（`workflowImage` / `workflowVideo`），
上一版用了什么会被继承，所以「这次换一个」只要给一次。

## 比例怎么流

**视频比例跟首帧图，不跟模板默认。** H3 这类模板的宽高由 `ResolutionSelector`（比例档位 + 百万像素）
现算，没有可写的数值字段——光推 width/height 会落空，视频就一直是模板写死的那档（16:9），
首帧是竖图也会被按 16:9 重构图。所以走档位：

`面板显式指定的档位` > `首帧图实际像素吸附到最近档位` > `上一版继承的`

档位表从模板 `aspect_ratios` 读（缺省用内置 8 档，实测自 ComfyUI 的 `object_info`）。
面板上的「比例」下拉选「跟随首帧（自动）」就是让它自己定；Inspector 会写清这一版的比例从哪来。
回归检查：`npm run check:aspect`。

**生图节点没有首帧可跟**，它听下游出片节点已经定死的档位：

`面板显式指定的档位` > `下游出片当前版本的档位` > `上一版继承的`

只有「面板指定」这类来源的档位能回流上游；下游若是从首帧吸附来的，那比例本来就是从这张图算的，
再喂回去会绕成环，所以不采纳（`downstreamAspect` 里的 `usable` 就是这道闸）。

## 内置助手（AI 原生）

画布右边有个「✦ 助手」标签页。它直接改这张画布：建节点、写提示词、连线、跑版本、抽卡、切引脚。

- **它凭什么能控制**：`server/agent.ts` 里 29 个工具，直接调 server 的能力函数（同一进程，不走 HTTP 自己调自己）。模型循环调用工具，直到事情做完。
- **过程全可见**：一轮对话走 SSE（`POST /api/agent/chat`），助手说的话、每次工具调用（名称/参数/耗时/结果摘要）逐条推给面板，没有黑盒等待。
- **删东西要人点头**：删节点、删版本、杀 8888 走审批门（`GUARDED`），面板上弹「批准 / 拒绝」，超时未响应视为拒绝。
- **提示词优化**：`optimize_prompt` 工具 + Inspector 里的「✦ AI 优化」按钮。两套语境分开——生图写静态画面（主体/构图/光/材质/镜头），出片写 i2v 运动（主体动作/运镜/时间演进），不重述首帧已有的静态外观。一次出 3 条候选，点一条填回去。
- **优化 ≠ 重写（精修契约）**：节点上已经有定稿的词时，那段词会作为「精修对象」送进去，模型只许做四件事——规范化格式、补足缺失维度、精确措辞、改语病；主体/场景/结构/台词是冻结的，候选之间也不许拿运镜与画风当差异卖点，每一处改动都要逐条报回来（Inspector 里显示「改动 N 处」）。要真的推翻重来就在面板上勾「允许重写」。少了这层契约，模型会把既有词当成一句「想法」，重写成一个新片子——那是改版，不是优化。
- **参考画面（剧情连贯的关键）**：优化和评审都会先把项目里已出的画面收集成参考图送进多模态请求，每张带角色标签——`首帧`（出片节点的上游图，就是 i2v 的第 0 帧）、`本节点当前版本`、`上一镜结尾`、`下一镜开头`；视频一律抽首/尾帧切片而不是整段。同时带上**剧情线**（按画布从左到右排的各镜头实际提示词）。所以它写词时会说「首帧是带余烬的碎石山脊，上一镜结尾是沙丘且斗篷露出红色内衬，别让风把红内衬翻到正面」。
  - 来源三种：自动（上游链路 + 剧情相邻镜头）、显式指定（`node:标题@v2` / `take_xxx` / `path:D:\参考图.png`）、界面上勾选与填路径。取不到的参考落到 `skipped` 里说清楚，不静默吞掉。
  - 收集逻辑在 `server/refs.ts`，抽帧用 `media.grab`（缩略图按 take 缓存，抽一次就够）。
- **改完画布自动刷新**：工具执行后推 `project` 事件，前端立刻重拉，不用手动刷新。
- **抽卡评审（看图打分 + 对照连贯度）**：`review_takes` 工具 + Inspector 里的「✦ AI 评审最近 6 版」。把产物用 ffmpeg 压成缩略图（长边 640），以 data URL 送进多模态请求——**模型真的看到了画面**，能指出「左侧悬浮方块上有乱码伪文字」这种只有看才能发现的事。每版给 0-100 分和一句评语，排序列出，一键把最优设为引脚；分数回写到 `take.params.aiReview`，刷新页面还在。评审还会把上游/相邻镜头当**对照画面**一并送进去（不评分、不编号），连贯度接不上就扣分并写进硬伤。
- **失败诊断**：`diagnose` 工具 + 失败版本旁边的「✦ 诊断」。先过本地规则表（显存不够 / 实例没起 / 缺首帧 / 模板被拒 / 路径错 / 超时 / 服务重启中断），规则比模型判得又快又准还免费；不命中才把错误原文和环境一起交给模型。结论带证据（命中的错误片段 + 实例探测结果）。
- **比例也归它管**：生图节点没指定档位时，跟下游出片节点已经定死的档位走（见下节）；`board` 里会把不一致的写出来。
- **渐进式披露（省 token）**：工具描述只放「这个工具干什么」+ 一行清单（算子只列 `id(名字)`），细节按需查——`ops_help` 查某个算子的入边要求与全部参数，`templates` 查模板。清单类内容常驻进每轮上下文是纯烧 token，一份算子参数表就值 200+ 字。`npm run check:ai` 里有护栏盯着这件事（最长描述 ≤260 字、全部描述合计 ≤1800 字）。

模型配置在「⚙ 设置 → LLM · 助手」里改，落 `data/llm.json`（baseUrl / key / 模型 / temperature / maxTokens / 超时），改完按「测一下」当场知道通不通。
优先级：**环境变量 > data/llm.json > 项目根 `.env`**。`.env` 仍然认，当兜底和临时覆盖用：

```bash
TAKEBOARD_LLM_BASE_URL=https://…/v1     # 任何 OpenAI 兼容端点
TAKEBOARD_LLM_API_KEY=sk-…
TAKEBOARD_LLM_MODEL=…
# 网关要额外请求头时：TAKEBOARD_LLM_HEADERS='{"x-some":"v"}'
```

key 只以脱敏串回前端（`sk-2••••••Vjjf`），完整值不出服务端；面板里 key 留空 = 不改，要清掉按「删掉存的 key」。
接口：`GET/PUT /api/llm`、`POST /api/llm/test`。回归检查：`npm run check:config`。

**本机默认项目设置**（画幅 / 时长 / 像素预算 / 模板 / ffmpeg 这些「换项目也不用重配」的项）存 `data/defaults.json`：
设置面板里「存为本机默认」把当前项目这一套存下来，以后**新建的项目直接带着它出生**；老项目按「套用本机默认」一键套上。
接口：`GET/PUT /api/defaults`。

真调一次模型的冒烟：`npm run check:agent -- --project <id> --ask "画布上有什么"`

改了工具表要重启服务再冒烟（`powershell -File scripts\restart.ps1`）——服务是 `tsx server/index.ts`，没有 watch，不重启跑出来的还是旧工具表的结论。核验：`curl http://127.0.0.1:4317/api/agent/status` 的 `tools` 数要跟 `TOOLS.length` 对得上。

## 算子节点（剪辑动作也在画布上）

算子清单的唯一真相源是 `shared/ops.ts` —— 前端下拉、参数面板、助手工具描述全从那儿来，加算子不用改三处。

| 算子 | 干什么 |
| --- | --- |
| concat | 按入边顺序首尾接成一条片子，自动统一分辨率与帧率 |
| **xfade** | **过渡拼接** —— 镜间叠化/黑场/划像等 16 种过渡，时长可调；成片时长 = 各镜之和 − 过渡 × 过渡处数 |
| trim | 从某一秒起截一段 |
| poster / firstframe | 抽某一时刻 / 第一帧当图 |
| **lastframe** | **抽最后一帧** —— 接戏的快捷动作：这镜结尾什么样，下一镜就从它开 |
| extractaudio | 把片子的声音单独抽成素材 |
| muxaudio | 配音 / 加 BGM：第一路视频是画面，其余入边当声音；原声可留可弃、音量可调、短了自动循环 |
| mixaudio | 只混声音（配音 + BGM → 一条音轨），给了时长就补静音补到精确 |
| subtitle | 文本烧成硬字幕，旁挂一份 srt 随时改样式重烧 |

- 产物一样进 take 栈、一样能切引脚回退，跟跑模型出的图/片没有区别。
- Inspector 里选算子只填该算子的参数（控件形状由 ops.ts 的定义决定），另有 **⚡尾帧 / ⚡首帧 / ⚡抽音轨** 三个快捷按钮。
- 助手有 `op` 工具（描述里只列 `id(名字)`）加一个 `ops_help` 工具（查单个算子的入边与参数），所以「把这一镜的尾帧抽出来接下一镜」它能自己做，参数不用猜。

### 接戏（尾帧 → 下一镜首帧）

「这镜结尾什么样，下一镜就从它开」是连贯的命门，所以它是一个动作，不是一串手工操作：

- 预览台的 **⤳ 接下一镜**（或 Inspector 里的 **⤳ 尾帧接下一镜**）一步做完：建/复用尾帧算子节点「尾帧·<本镜>」→ 连上本镜跑 lastframe → 把尾帧连到下一镜。
- 那条连线标了 `role: 'firstframe'`：**出片只认它**，别的图入边让位（后面再连别的图也抢不走）。同一镜重复接戏是「改接」，不是叠一堆抢首帧。
- 接过来的尾帧还没跑完时，出片会明说「首帧「尾帧·X」还没跑完或没成」，**不偷偷退回旧图** —— 退回等于静默接错戏，画面看着像新镜、其实开在上一版旧首帧上。
- 首帧来源看得见：Inspector 里显示「首帧：← 「尾帧·镜头A」 v1」；接口 `GET /api/projects/:id/firstframe?nodeId=`；助手有 `handoff_shots` / `first_frame` 两个工具。
- 不传 to 就接画布上 x 排在它后面的那一镜（剧情顺序），已经接戏了再点就是改接。

## 剧情模式（一条龙）

剧情是数据的真相源，画布是它的实例化：导入剧本或让助手写一份分镜表 →「填模板」每镜建一对节点（首帧 + 出片），词写进节点 `draft` → 一条龙出初版成片。

顺序是硬的 —— 两块实例抢同一块显存，并行就是一起 OOM：

**填模板 → 精修首帧词 → 逐镜出首帧（8888）→ 释放生图实例让出显存 → 逐镜（精修出片词 → 接上一镜尾帧 → 出片，8188）→ 合成成片**

四个关键点：

- **词默认走 H3 技能**：精修装 `h3-video-prompt-enhancer`，把糙词写成规范格式。精修结果**同时写回剧情和节点 `draft`** —— `runNode` 取词时 `draft.prompt` 压过剧情里的词，只写剧情不写 draft，精修完跑出来的还是旧词。
- **出片词留到每镜出片前才精修**：要接上一镜的结尾，得先有上一镜的尾帧。一次跑完再精修，模型只看得到文字；现在 `collectRefs` 会把上一镜的**尾帧切片**当参考图送进多模态请求，模型是看着上一镜的结尾写下一镜的。
- **接戏默认开**：出片前把上一镜尾帧接成本镜首帧（标 `role: 'firstframe'` 的边），画面真的连得上；接不上就退回本镜自己的首帧（硬切），不因为接戏失败作废整镜。不想要就在界面上关掉「接戏」。
- **失败自动重试**：首帧 / 出片 / 接戏每步失败重试 2 次（`retries`），**叫停不重试**。一镜最终没成，下一镜照跑（有上一镜尾帧可接就接），成片前明确报「缺 N 镜」，不静默出一部残片。

界面上「精修词」和「接戏」两个勾选默认开着；单镜卡片上的「跑」用现有词直接重跑，不再精修（免得把已经调好的词又改写一遍）。

接口 `POST /api/projects/:id/story/run`（body：`beats` / `refine` / `handoff` / `retries` / `film`），助手工具 `run_story` 同一套参数；离线自检 `npm run check:story` 覆盖重试的四种情形（第二次成功 / 一直挂试满 3 次 / 叫停不重试 / `retries=0`）。


## 预览台（边剪边看）

画布下方是一条类剪映的预览带，镜头按**剧情顺序（x 轴）**连着播，不用先渲染成片：

- 双 video 元素轮换：当前镜在播，另一个槽把下一镜 preload 好，切镜不黑屏。
- 时间线按每镜时长分宽，缩略图当底、当前镜高亮 + 播放头；点哪一镜跳哪一镜。
- 序列来源可选：整张画布，或「到某一镜为止」（那时把它自己也算进去，能看到配好音/烧好字幕的那一版）。
- **算子产物不算镜头**（成片/字幕版/配音版不进序列），否则出一次成片就会把上一次的成片再拼一遍。
- 「⤓ 出成片」照这条序列在画布上建（或复用）一个算子节点，把镜头连上去跑拼接 —— 产物照旧进 take 栈，出问题能顺着画布查。
- 序列也能从接口拿：`GET /api/projects/:id/sequence?end=<nodeId>`；助手有 `sequence` / `export_film` 两个工具。
- 边剪边接：预览台里就能点 **⤳ 接下一镜**（见上节「接戏」），改完立刻能看到下一镜的首帧换了谁。
- **镜间过渡**：预览台里选过渡（叠化/黑场/划像…16 种，或硬切）与每处时长，存进项目设置 —— 之后每次「⤓ 出成片」都按它走（`exportFilm` 自动决定用 `xfade` 还是 `concat`）。头部的「成片时长」已经扣掉过渡重叠。
  - **预览里是真重叠**：镜尾前 T 秒就把另一槽起播，两个 video 同时在跑，一个淡出一个淡入 —— 不是等这镜播完（画面已经僵在最后一帧）再淡入下一镜。
  - 预览只做叠化近似（`cross-in` / `cross-out` 两个类 + CSS transition，时长用收紧后的值）；划像、圆开圆合这些形状只有成片里才有，所以选了非硬切时旁边会标一句「预览按叠化」。
  - 过渡时长会被自动压到「最短的那一对的一半」以内；压到 0.05s 以下就退回硬切。实际用了多少记在 take 的 `params.transitionUsed`，不静默吞掉。
  - 没音轨的镜用 `anullsrc` 补静音再走 `acrossfade` —— 少一路就整条音轨链断掉，宁可用静音也别丢声音。

## 跟 ComfyUI 怎么接的

- 模板直接读 Easel 的工作流：`skills/shared/comfy/workflows/*.json`（配 `.meta.json` 默认值）
- **旋钮是自动发现的**，不写死节点号：顺着采样器的 positive/negative 连线找文本节点，
  顺着连线回溯找尺寸/种子/时长。模板改一次节点号就全变，写死必炸。
- 连线驱动的字段（H3 的 `131.width` 实际是 `["115",0]`）**一律不直接写**——
  要么回溯到源节点的数值输入，要么干脆不给这个旋钮，绝不写坏工作流。
- 生图走 **8888**（z-image / sdxl 系），出片走 **8188**（MiniMax H3）。两个实例的模型不通用，
  模板 `.meta.json` 里的 `host` 说了自己装在哪台——Inspector 的模板下拉按实例过滤，
  生图节点不会看到只装了 H3 的模板。
- 两个实例都能**一键起、一键关**：「⚙ 设置」面板，或 `POST /api/machine/instances/:id/start|stop`（id = `image` / `video`）。
  配方（命令 / cwd / 端口）存 `data/machine.json`。关闭只杀监听目标端口的进程，Takeboard 自己（4317）拒绝被关，
  还有作业在跑会先拦一道（要 force）。起不来会把日志尾巴一起返回，不用去翻文件。
- 出片前自动**释放生图实例 8888**（`releaseImageBeforeVideo`，默认开）。
  自动流程仍只认生图端口——`releaseImagePort(8188)` 照样抛错：自动流程没有判断力，
  不许它顺手把出片实例关了；人手动关走 `machine.stopInstance`，那边允许 8188，但有作业在跑会拦。
- 作业的 `prompt_id` 落盘：服务重启会**接着把产物收回来**，不会变成僵尸 take。
